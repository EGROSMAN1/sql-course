שפת DAX — חמשת התפקידים

DAX — Data Analysis Expressions — היא שפת הנוסחאות של מודל הנתונים. הסינטקס מזכיר Excel, אבל אקסל עובד על תאים בודדים ו-DAX על עמודות וטבלאות שלמות.

מדדים (Measures)

הכוח האמיתי: חישובים דינמיים שמשתנים בזמן אמת לפי מה שהמשתמש בוחר. סך הכנסות, ממוצע ללקוח, אחוז רווח.

02

עמודות מחושבות

נתון חדש לטבלה קיימת, מחושב לכל שורה בנפרד — למשל מחיר יחידה × כמות = סך מכירה לשורה.

04

Time Intelligence

כלל הזהב — דחיפת העיבוד אחורה

Roche's Maxim: בצעו כל טרנספורמציה כמה שיותר "אחורה" בשרשרת — קרוב ככל האפשר למקור הנתונים.

2

אותו דף, אותו סלייסר Product[Color] = "Red" שמציג $21,597,891. ההבדל היחיד — מה כתוב בארגומנט הפילטר של CALCULATE.

מחליף

$9,602,851

DAX
CALCULATE ( [Total Sales],
    Product[Color] = "Blue" )

פתק חדש על אותה עמודה מפיל את הישן. הסלייסר האדום הוחלף בכחול.

מוחק

$109,809,274

DAX
CALCULATE ( [Total Sales],
    ALL ( Product ) )

הפתק נזרק, וכלום לא נכנס במקומו — כל המוצרים חוזרים פנימה.

חותך

$7,913,702

DAX
CALCULATE ( [Total Sales],
    FILTER ( Product,
      Product[List Price] > 3000 ) )

הסלייסר נשאר, ונוסף עליו תנאי — מקבלים את החיתוך: אדומים וגם יקרים.

מוחק ובוחר

$17,823,781

DAX
CALCULATE ( [Total Sales],
    FILTER ( ALL ( Product ),
      Product[List Price] > 3000 ) )

ALL פתח את כל 397 המוצרים, ו-FILTER בחר מתוכם 13 — בלי קשר לסלייסר.

המלכודת מהדאטה: סלייסר על Product[Category] = "Clothing", ומבקשים אדום. עם FILTER ( Product, … ) תקבלו $0 — כי אין ביגוד אדום שנמכר בכלל. עם FILTER ( ALL ( Product ), … ) תקבלו $21,597,891. כשהמדד "מקולקל" — כמעט תמיד חסר ALL.
✓ שתי השאלות לפני כל מדד: (א) יש לי תנאי לבדוק? ← FILTER, או בוליאני אם התנאי פשוט. (ב) להתעלם ממה שמסונן בדף? ← ALL בפנים. שתי תשובות "כן" = FILTER ( ALL ( … ), … ).

שלושה כללים שמונעים 95% מהתקלות

01

שם הטבלה — מההשלמה האוטומטית

במודל יש טבלאות כפולות (SalesTerritory וגם Sales data_Territory). מתחילים להקליד ובוחרים מהרשימה. מדד שמצביע על טבלה שהוויזואל לא משתמש בה = ריק.

02

המדד תמיד בסוגריים מרובעים

[Total Sales] ולא SUM ( … ) גלמי. SUM בתוך פונקציית חלון מתעלם משורות ההקשר — וכל המדינות יוצאות באותו מקום.

03

כלל הריק — רמת הפירוט

הפונקציות עונות רק כשהוויזואל נמצא ברמת הפירוט של הרשימה. הרשימות כאן ברמת Country ← המדדים חיים בטבלה שבשורותיה Country. בקארד או בשורת Total — התנהגות אחרת.

הערת שמות: במדריך המקורי המדד נקרא [total salse] והטבלה SalesTerritory. כאן נשתמש ב-[Total Sales] — המדד שבנינו בפרק IV — ובאותה טבלת SalesTerritory. אם השמות אצלכם שונים, החליפו אותם ותו לא.

1 · ORDERBY — לפי מה מסתדרים

ברירת המחדל היא ASC

מיון לפי כסף דורש מדד

03

6 · OFFSET — השכן, צעד למעלה או למטה

OFFSET זזה במרחק יחסי ממני בשורת המסדר: ‎-1 = השורה שמעליי, ‎+1 = שמתחתיי. זו הפונקציה של "כמה חסר לי כדי לעקוף את הבא בתור" — השוואה לשכן, לא לאלוף.

שליטה עדינה בהקשר — KEEPFILTERS · ALLSELECTED · ALLEXCEPT

קשרים בזמן ריצה — USERELATIONSHIP · CROSSFILTER · TREATAS

שלוש פונקציות שנוגעות בקשרים עצמם — לזמן החישוב בלבד, בלי לשנות את המודל.

USERELATIONSHIP — מפעילה קשר פסיבי

בין שתי טבלאות יכול להיות יותר מקשר אחד, אבל רק אחד פעיל. USERELATIONSHIP מפעילה את הפסיבי — בתוך המדד בלבד.

התבנית הקלאסית: אותה טבלת תאריכים, פעם לפי תאריך הזמנה ופעם לפי תאריך משלוח

DAX
Sales By Ship Date = CALCULATE (
    [Total Sales],
    USERELATIONSHIP ( Sales[ShipDateKey], 'Date'[DateKey] )
  )
לא ניתן להדגמה על המודל שלנו: ב-AdventureWorks כפי שבנינו אותו יש קשר יחיד Sales[OrderDateKey] → Date[DateKey], ואין קשר פסיבי שני. כדי לנסות — הוסיפו במודל קשר נוסף מ-ShipDateKey ואל תסמנו אותו כפעיל. שני כללים: הקשר חייב להתקיים במודל, ו-USERELATIONSHIP חייבת לשבת בתוך CALCULATE.

CROSSFILTER — משנה כיוון סינון

משנה זמנית את כיוון הסינון של קשר קיים — Single, Both, או None — רק בתוך החישוב.

DAX

    DISTINCTCOUNT ( Product[ProductKey] ),
    CROSSFILTER ( Sales[ProductKey], Product[ProductKey], BOTH )

הכיוון הרגיל במודל הוא מהממד אל העובדה. עם BOTH הסינון זורם גם חזרה — למשל "כמה מוצרים בכלל נמכרו בשנה שנבחרה". עם NONE מנתקים את הקשר לרגע. זו האלטרנטיבה המדודה לסינון דו-כיווני גלובלי, שאותו הכרנו בשיעור 2.

אם ההקשר מצומצם לערך יחיד — מחזירה אותו. אם לא — מחזירה את ברירת המחדל. סוף לתבנית המסורבלת של IF ( HASONEVALUE ( … ), VALUES ( … ) ).

ערכים, מפתחות והקשר — COALESCE · COMBINEVALUES · CONTAINSROW · EARLIER

COALESCE — הערך הראשון שאינו ריק

DAX
Sales Or Zero = COALESCE ( [Total Sales], 0 )
בטבלה שבשורותיה Country, מדינה בלי מכירות תציג ריק. עם COALESCE היא תציג 0 — וחשוב מכך, השורה תפסיק להיעלם מהוויזואל. הרבה יותר קריא מ-IF ( ISBLANK ( … ), 0, … ) כי הביטוי מחושב פעם אחת בלבד.

COMBINEVALUES — מפתח משולב

DAX
Territory Key =
  COMBINEVALUES ( "|",
      SalesTerritory[Country],
      SalesTerritory[Region] )
✓ התוצאה: United States|Southwest. המפריד מובטח לא להופיע בטעות בתוך הערכים, ולכן זה בטוח יותר משרשור עם &. השימוש הנפוץ: מפתח מורכב לאבטחת שורות, או קשר וירטואלי על שתי עמודות עם TREATAS.

CONTAINSROW — האם השילוב קיים

DAX
Is Apparel =
  CONTAINSROW ( { "Clothing", "Accessories" },
      SELECTEDVALUE ( Product[Category] ) )
הקשר ל-IN: האופרטור IN שהשתמשנו בו בפרק VII הוא בדיוק סוכר תחבירי ל-CONTAINSROW. הכוח האמיתי מתחיל כשבודקים שילוב של כמה עמודות יחד — CONTAINSROW ( Table, val1, val2 ) — משהו ש-IN לא יודע לעשות על טבלה וירטואלית.

EARLIER — הקשר שורה חיצוני

בעמודה מחושבת אפשר לפתוח הקשר שורה שני (למשל בתוך FILTER). EARLIER מאפשרת להתייחס לערך של השורה מההקשר החיצוני יותר.

עמודה מחושבת בטבלת Product: דירוג המוצר בתוך הקטגוריה שלו

DAX
Rank In Category =
  COUNTROWS (
      FILTER ( Product,
        Product[Category] = EARLIER ( Product[Category] )
          && Product[List Price] > EARLIER ( Product[List Price] )
      )
  ) + 1
איך לקרוא את זה: ה-FILTER פותח הקשר שורה חדש שרץ על כל 397 המוצרים; EARLIER מחזירה את הערכים של המוצר שעליו אנחנו עומדים בעמודה. סופרים כמה מוצרים באותה קטגוריה יקרים ממני, ומוסיפים 1.
✓ הערה מקצועית: מאז שהוצגו משתנים (VAR), EARLIER כמעט לא נחוצה — כותבים VAR CurrentCat = Product[Category] ומשתמשים במשתנה. עדיין חשוב להכיר אותה, כי היא מופיעה בכל קוד DAX שנכתב לפני 2015.

שאלות ותרגול

שאלה אחת בכל פעם, ארבע אפשרויות, משוב מיידי עם הסבר. כל השאלות עוסקות ב-M וב-DAX בסיסי בלבד.

מה מתאר נכון את חלוקת התפקידים בין M ל-DAX?

הסבר: M היא שפת ה-ETL של Power Query, ו-DAX היא שפת החישוב של מודל הנתונים.

מתי רץ קוד M?

הסבר: אחרי הרענון העבודה הסתיימה והטבלה "נצרבת" — היא קבועה עד הרענון הבא.

מתי רץ DAX?

הסבר: זה מה שהופך מדד ל"חי": כל סלייסר וכל קליק מפעילים חישוב מחדש.

איזו שפה רגישה לאותיות גדולות וקטנות?

הסבר: ב-M ‏Table.AddColumn עובד ו-table.addcolumn יזרוק שגיאה. DAX אינה רגישה לאותיות.

מה מכיל מבנה let … in ב-M?

הסבר: בין let ל-in מוגדר שלב אחרי שלב, וכל שלב נשען על הקודם.

לפי כלל הזהב (Roche's Maxim), איפה עדיף לבצע טרנספורמציה?

הסבר: סדר העדיפות: מסד הנתונים ← Power Query ← DAX. ככל שאחורה יותר, המודל קל ומהיר יותר.

רוצים טבלה חדשה שתמשיך מהשלבים של טבלה קיימת ותתעדכן איתה. מה בוחרים?

הסבר: Duplicate יוצר עותק מנותק; Reference ממשיך מהשאילתה המקורית, וכל שינוי בה זורם הלאה.

גזרתם DimCustomer מ-Sales וקיבלתם 18,485 שורות במקום 18,484. מה קרה?

הסבר: המפתח 1- מייצג "לא רלוונטי". תמיד לשאול: מי מסתתר במפתחות שלי?

מהו התנאי הראשון לטבלת תאריכים תקינה?

הסבר: בלי רציפות, פונקציות Time Intelligence יחזירו תוצאות שגויות. אצלנו: 1,461 ימים רצופים.

הסבר: הסימון מודיע למנוע שזו טבלת התאריכים של המודל ומהו מפתח היום הייחודי שלה.

אילו שלושה אובייקטים DAX יודעת ליצור?

הסבר: רוב העבודה היומיומית היא מדדים; טבלאות מחושבות הן יחסית נדירות.

צריך לסכם מספרים לוויזואל. מה כותבים?

הסבר: הכלל הזהב: מסכמים מספרים ← Measure. מסווגים שורות ← Column.

מה נכון לגבי עמודה מחושבת?

הסבר: העמודה מחושבת פעם אחת ברענון ואז יושבת במודל — בדיוק כמו עמודה שהגיעה מהמקור.

מה נכון לגבי מדד?

ראיתם בנוסחה [Total Sales] — סוגריים מרובעים בלי שם טבלה. מה זה?

מה SUM מקבלת כארגומנט?

איך AVERAGE מתייחסת לתאים ריקים?

מה COUNTROWS מקבלת?

לקוח אחד קנה 25 פעמים. מה יחזירו COUNT ו-DISTINCTCOUNT על CustomerKey?

הסבר: ולכן לשאלה "כמה לקוחות?" התשובה היא תמיד DISTINCTCOUNT.

למה משתמשים ב-DIVIDE ולא בסלאש?

הסבר: תא אחד עם מכנה אפס מספיק כדי להפיל ויזואל שלם. במדדים מקצועיים לא משתמשים בסלאש.

מה הפרמטר השלישי של DIVIDE?

הסבר: הוא רשות. השמטתם? יוחזר Blank שקט.

מה היתרון בכתיבת מדדים בשכבות (מדד שקורא למדד)?

התחביר הנכון: הטבלה שעליה רצים ראשונה, והתנאי הלוגי שני.

התחביר הנכון: הטבלה ראשונה — היא זו שמנוקה — ואחריה העמודות שיישארו מסוננות.

מהו התחביר התקין של ALLSELECTED?

עמודת החלוקה של PARTITIONBY חייבת להופיע גם…

5 עמודה מחושבת — רווח ודגל הפסד

6 SWITCH — שלוש מדרגות עסקה

10 ALL ואחוז מהסך הכולל

שחררו את הפילטרים כדי לקבל מכנה קבוע — ומזה בנו אחוז.

שלבמה עושים
1שני מדדים חדשים
2בנו טבלה: Category בשורות, [Total Sales] ו-[% of Total] בערכים
3עצבו את המדד כאחוז
DAX
All Sales = CALCULATE ( [Total Sales], ALL ( Sales ) )
 
% of Total = DIVIDE ( [Total Sales], [All Sales] )
✓ שורת Bikes תציג 86.2%, ועמודת האחוזים תסתכם ב-100%. בלי ALL — כל שורה תציג 100%.

11 דירוג מדינות עם RANK

בנו טבלה שבשורותיה SalesTerritory[Country] והוסיפו לה עמודת דירוג.

שלבמה עושים
1מדד חדש בטבלת Measures
2שימו את [Total Sales] ליד הדירוג בוויזואל
3שימו לב שחייבים לכתוב DESC במפורש
DAX
Country Rank = RANK (
    ALL ( SalesTerritory[Country] ),

  )

12 סכום מצטבר עם WINDOW

הוסיפו לאותה טבלה עמודת מצטבר, ובדקו את עצמכם בשורה האחרונה.

שלבמה עושים
1מדד חדש — שימו לב ל-CALCULATE שעוטף
21, ABS = מתחילים בראש הרשימה · 0, REL = עוצרים אצלי
3החליפו את 0, REL ב-3, ABS וראו מה קורה
DAX
Running Total = CALCULATE (
    [Total Sales],
    WINDOW ( 1, ABS, 0, REL,
      ALL ( SalesTerritory[Country] ),
      ORDERBY ( [Total Sales], DESC )
    )
  )
✓ השורה האחרונה חייבת להיות $109,809,274 — סך המכירות הכללי. עם 3, ABS תקבלו $90,008,697 קבוע בכל שורה.
