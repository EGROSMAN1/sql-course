Chapter I · Two languages, two engines

The M language — the five roles

M It's a functional scripting language that runs behind the scenes of Power Query. Every click in the graphical interface translates into a step written in M — you're writing M even without knowing it.

01

Connecting to sources

Excel, files, databases like SQL Server and-Oracle, API and websites — a single entry point for all the data.

02

Data cleaning

Removing empty and duplicate rows, handling errors, replacing values and changing data types — for example converting text to a date.

03

Reformatting

Structural operations: splitting columns, grouping Group By, and turning rows into columns and vice versa Pivot / Unpivot.

04

Combining tables

Merge — merge by key, or Append — one appended below the other. From different sources into one clean table.

05

The process is saved as a fixed set of steps. Click refresh — and all the cleanup steps rerun on the updated data.

The key point: M works at the preparation stage — before the data is displayed or analyzed. Write it once ← runs on every refresh, forever.

The DAX language — the five roles

DAX — Data Analysis Expressions — is the formula language of the data model. The syntax resembles Excel, but Excel operates on individual cells while DAX operates on entire columns and tables.

01

Measures (Measures)

The real power: dynamic calculations that change in real time based on what the user selects. Total revenue, average per customer, profit percentage.

02

New data for an existing table, calculated per row — for example unit price × quantity = total sale per row.

03

brand-new tables built from the existing data — a dates table, a summary table, a parameters table.

Time Intelligence

Comparisons over time: YTD, this month vs. the same month last year, moving averages.

Chapter I · Two languages, two engines

The golden rule — pushing the processing back

Roche's Maxim: Perform every transformation as far "back" in the chain as possible — as close as possible to the data source.

1

The database

SQL / Database. If the transformation can be done here — this is the preferred option. The server does the work, not the report.

2

Power Query

The M language. If it can't be done in the database — clean and shape it here, once per refresh.

3

DAX

Data Model. Only for calculations that must be dynamic and respond to the end user.

Order of priority: Data source ← Power Query ← DAX. The further back, the lighter and faster the model.
✓ The common mistake: building a calculated column in DAX when it could have been calculated in M. The column takes up memory on every refresh, forever.

Chapter III · Intro to DAX

Three things DAX knows how to create

three objects, and each has its own place. The difference between them is the most important difference in the lesson.

Calculated Table

A whole new table

When? When you need a table that does not exist in the source — a dates table, a parameter table. Relatively rare: most tables come from M.

Calculated Column

A value per row

When? When you need a per-row value for filtering or grouping — for example Profit for every sales row. Calculated on refresh, stored physically, takes up memory.

⭐ Measure

Live running calculation

When? Almost always — for every summary and calculation. Computed on every interaction, not stored. This is 90% of the lesson.

✓ The golden rule: Summing numbers? ← Measure. Classifying rows? ← Column.

Chapter VI · Iterators

SUMX — Row-by-Row Calculation

Calculates an expression inside every row — and only then adds up the results. That's what SUM doesn't know how to do.

DAX
Revenue Before Discount =
  SUMX ( Sales,
      Sales[Order Quantity] * Sales[Unit Price] )
$110,336,782Revenue before discountSUMX
  1. Opens the Sales tableand goes row by row.
  2. In each row: quantity × priceThe calculation runs within the context of the single row.
  3. Combines the 121,253 resultsand returns a single number.
Why not SUM? because SUM only accepts a single column — it doesn't know how to multiply two columns. For multiplication within a row you need an iterator.
✓ The siblings of SUMX: AVERAGEX · MAXX · MINX · COUNTX — the exact same syntax, a different ending.
