דשבורד מכירות — הכנה ומבנה המטלה

דשבורד בעמוד אחד שכל המספרים בו מגיעים ממדדים שאתם כותבים מאפס, עם חיווי צבע אוטומטי למצב המדינות. עובדים על AdventureWorks_Sales.xlsx — המודל מהשיעורים הקודמים. 25 תרגילים, כל אחד בדף נפרד ועם פתרון מלא. שימו לב: ההורדה והתרגול הם במחשב בלבד — Power BI Desktop אינו קיים בטלפון.

לפני שמתחילים — בדקו את הקשר הפעיל. במסך Model ודאו שהקשר הפעיל (הקו הרציף) בין Sales ל-Date הוא DateKey → OrderDateKey. בטבלת Sales יש שלושה מפתחות תאריך (Order · Due · Ship), והזיהוי האוטומטי בוחר אחד מהם שרירותית. קשר שגוי = כל גרף זמן יספר סיפור לא נכון — תראו את זה בתרגיל 2.5.

מילון סוגריים. Table[Column] = עמודה · [מדד] = סוגריים מרובעים בלי שם טבלה. לכל מדד: קליק ימני על טבלת Sales בחלונית Data ← New measure ← הנוסחה ← Enter. השם חייב להיות בדיוק כפי שמופיע בתרגיל.

רמזור והרכבה

עיצוב מותנה בחוקים על גרף המדינות, ואז הרכבה, יישור ובדיקה עצמית שהדשבורד מספר סיפור אחד.

כל המספרים אומתו ב-pandas מול הקובץ

1.1 · Total Sales — מדד הבסיס

צרו מדד בשם Total Sales שמסכם את עמודת Sales[Sales Amount].

Total Sales = SUM ( Sales[Sales Amount] )
  1. יצירהקליק ימני על טבלת Sales ← New measure
  2. בדיקהגררו לקארד ריק כדי לוודא שהמספר מופיע

למה SUM ולא עמודה מחושבת: עמודה מספרית אחת שמסכמים. מדד "חי" — הוא מחושב מחדש בכל בועת סינון, ולכן אותו מדד ישרת קארד, גרף וטבלה בלי לכתוב אותו שוב.

תוצאה: $109,809,274 — מספר העוגן של כל המטלה.

1.2 · Total Orders — כמה הזמנות באמת

צרו מדד בשם Total Orders שסופר הזמנות ייחודיות על בסיס 'Sales Order'[Sales Order].

Total Orders = DISTINCTCOUNT ( 'Sales Order'[Sales Order] )

שימו לב לעמודה: Sales Order ולא SalesOrderLineKey. הזמנה עם כמה פריטים מופיעה בכמה שורות; DISTINCTCOUNT מסנן את הכפילויות, בעוד COUNT היה מחזיר 121,253 — שורות, לא הזמנות.

תוצאה: 31,455 הזמנות מתוך 121,253 שורות מכירה.

1.3 · Avg Line Value — הממוצע

צרו מדד בשם Avg Line Value שמחשב את הממוצע של Sales[Sales Amount].

Avg Line Value = AVERAGE ( Sales[Sales Amount] )

ממוצע של מה בדיוק: זהו ממוצע לשורת פריט, לא ממוצע להזמנה. ממוצע הזמנה מתקבל מ-[Total Sales] / [Total Orders] ועומד על כ-$3,491 — פי כמעט 4. שתי שאלות עסקיות שונות לגמרי, ולכן חשוב לדעת מה בדיוק חילקתם.

תוצאה: $905.62 לשורת פריט.

1.4 · Bikes Sales — CALCULATE ראשון

צרו מדד בשם Bikes Sales שמחזיר את מכירות קטגוריית Bikes בלבד. השתמשו ב-CALCULATE עם [Total Sales] כביטוי ותנאי על Product[Category].

Bikes Sales = CALCULATE ( [Total Sales], Product[Category] = "Bikes" )

הלב של DAX: CALCULATE מריץ מדד קיים תחת פילטר חדש. שימו לב שהשתמשנו ב-[Total Sales] ולא כתבנו SUM מחדש — עקרון הלגו: שינוי אחד במדד הבסיס מתגלגל לכל המדדים שנשענים עליו.

תוצאה: $94,620,526.

1.5 · FY2020 Sales — CALCULATE שני

צרו מדד בשם FY2020 Sales שמחזיר את מכירות שנת הכספים FY2020 בלבד, עם תנאי על 'Date'[Fiscal Year].

FY2020 Sales = CALCULATE ( [Total Sales], 'Date'[Fiscal Year] = "FY2020" )

אותה תבנית, ממד אחר: ברגע שמבינים CALCULATE, כל "מכירות של X" הוא שורה אחת. שימו לב שהשנה כאן פיסקלית (יולי–יוני) ולא קלנדרית — FY2020 מסתיימת ביוני 2020.

תוצאה: $51,878,275.

1.6 · US Sales — מכירות ארה"ב

צרו מדד בשם US Sales שמחזיר את מכירות ארצות הברית בלבד, עם תנאי על 'Sales Territory'[Country].

US Sales = CALCULATE ( [Total Sales], 'Sales Territory'[Country] = "United States" )

המספר שמכתיב את כל הדשבורד: ארה"ב לבדה מייצרת יותר ממחצית העסק. נחזור אליה בפונקציות החלון — היא המדינה המובילה, והבסיס להשוואות "% מהמובילה".

תוצאה: $62,997,591 — 57.4% מכלל המכירות.

1.7 · Reseller Sales — לפי ערוץ

צרו מדד בשם Reseller Sales שמחזיר את המכירות דרך ערוץ ה-Reseller, עם תנאי על 'Sales Order'[Channel].

Reseller Sales = CALCULATE ( [Total Sales], 'Sales Order'[Channel] = "Reseller" )

תובנת ערוץ: שני שלישים מהעסק עוברים דרך משווקים ולא ישירות לצרכן. זו נקודת פתיחה לכל דיון על תלות בערוץ הפצה.

תוצאה: $80,450,597 (73.3%). היתרה — Internet: $29,358,677 (26.7%).

1.8 · Bikes % of Total — יחס

צרו מדד בשם Bikes % of Total — חלקה של קטגוריית Bikes מכלל המכירות. השתמשו ב-DIVIDE עם [Bikes Sales] ו-[Total Sales]. עצבו כאחוז.

Bikes % of Total = DIVIDE ( [Bikes Sales], [Total Sales] )
  1. העיצובסמנו את המדד ← Measure tools ← Format = Percentage

לגו טהור: מדד שבנוי משני מדדים קיימים, בלי אף SUM חדש. DIVIDE ולא סלאש — חלוקה באפס תחזיר ריק בשקט במקום שגיאה.

תוצאה: 86.2% — קטגוריה אחת מחזיקה כמעט את כל העסק.

1.9 · Country Rank — RANK

צרו מדד Country Rank שמדרג את המדינות לפי מכירות (הגבוהה = 1). השתמשו ב-RANK עם ORDERBY על [Total Sales] בכיוון יורד.

◆מה הדירוג של France, ולמה RANK עדיף על הקלדת מספרים ידנית?

Country Rank = RANK ( ALL ( SalesTerritory[Country] ), ORDERBY ( [Total Sales], DESC ) )

למה RANK ולא מספרים ידניים: הדירוג "חי" — סלייסר שנה או קטגוריה יסדר אותו מחדש לבד, כי ORDERBY ממיין לפי מדד. מספרים שהוקלדו ביד היו קופאים ברגע שהמשתמש מסנן.

שתי מלכודות: ברירת המחדל של ORDERBY היא ASC — בלי DESC המדינה החלשה תקבל מקום 1. ובתוך פונקציית חלון תמיד [מדד] ולא SUM גלמי, אחרת כל השורות יחזירו מקום 2.

תוצאה: France = 5. הדירוג המלא: US=1 · Canada=2 · Australia=3 · UK=4 · France=5 · Germany=6.

1.10 · Sales Running Total — WINDOW

צרו מדד Sales Running Total שמסכם מהמדינה המובילה ועד הנוכחית, באמצעות WINDOW ( 1, ABS, 0, REL, ... ).

◆מה הערך המצטבר בשורת Australia, ואיך בודקים תקינות בשורה האחרונה?

Sales Running Total =
CALCULATE (
    [Total Sales],
    WINDOW ( 1, ABS, 0, REL,
        ALL ( SalesTerritory[Country] ),
        ORDERBY ( [Total Sales], DESC, SalesTerritory[Country], ASC )
    )
)

ארבעת המספרים: 1, ABS = מתחילים תמיד בראש הרשימה (חלון שעומד במקום) · 0, REL = עוצרים אצלי (חלון שנע איתי). שובר-השוויון ב-ORDERBY מבטיח סדר יציב כששתי מדינות זהות.

1.11 · Running % — פארטו באחוזים

צרו מדד Running % — המצטבר מ-1.10 כאחוז מסך המכירות, עם DIVIDE. עצבו כאחוז.

◆כמה אחוז מצטבר עד סוף המדינה השלישית, ומה זה אומר עסקית?

Running % =
DIVIDE (
    [Sales Running Total],
    CALCULATE ( [Total Sales], ALL ( SalesTerritory[Country] ) )
)

מבנה המדד: המונה הוא המצטבר, המכנה הוא סך הכל משוחרר מסינון המדינה. בלי ALL המכנה היה מצטמצם לשורה עצמה וכל השורות היו מציגות 100%.

תוצאה: עד Australia (מקום 3) — 82.0%. הרשימה: 57.4% ← 72.3% ← 82.0% ← 89.0% ← 95.6% ← 100.0%. פארטו על צלחת: חצי מהמדינות מייצרות 82% מההכנסה.

1.12 · Gap To Above — OFFSET

צרו מדד Gap To Above — כמה כל מדינה מפגרת אחרי זו שמעליה. השתמשו ב-OFFSET ( -1, ... ) בתוך CALCULATE, וחסרו מ-[Total Sales].

◆איזו מדינה הכי קרובה לעקוף את זו שמעליה, ובכמה?

Gap To Above =
[Total Sales]
    - CALCULATE (
        [Total Sales],
        OFFSET ( -1,
            ALL ( SalesTerritory[Country] ),
            ORDERBY ( [Total Sales], DESC, SalesTerritory[Country], ASC )
        )
    )

1.13 · % of Leader — INDEX

צרו מדד % of Leader — כמה אחוז כל מדינה מהמובילה. השתמשו ב-INDEX ( 1, ... ) לשליפת מכירות המובילה, ו-DIVIDE.

◆מה ה-% of Leader של Canada — והאם "מקום שני" מספר את הסיפור המלא?

% of Leader =

    CALCULATE (
        [Total Sales],
        INDEX ( 1, ALL ( SalesTerritory[Country] ), ORDERBY ( [Total Sales], DESC ) )
    )

2.1 · גוון הצבע והרקע

בחרו גוון HEX אחד (למשל ב-coolors.co) — כל צבעי הדשבורד יהיו מהמשפחה שלו. לחצו על אזור ריק בקנבס ← Format your report page ← Canvas background ← גרסה בהירה של הגוון ← Transparency = 0%. הוסיפו כותרת: Insert → Text box ← "דוח מכירות AdventureWorks" בגופן גדול וצבע כהה מהמשפחה.

  1. רקעFormat your report page ← Canvas background ← גוון בהיר ← Transparency = 0%
  2. כותרתInsert ← Text box ← גופן גדול, צבע כהה מהמשפחה
  3. משמעת צבעגוון אחד + דרגות בהירות שלו. כל צבע נוסף חייב להצדיק את עצמו

בדיקה: אם אתם צריכים יותר משלושה צבעים כדי להסביר את הדשבורד — יש יותר מדי צבעים.

2.2 · הצורה — מגש ה-KPI

Insert → Shapes → Rectangle ← מתחו רצועה רוחבית מתחת לכותרת, במקום שבו ישבו ארבעת הקארדים. Format shape → Rounded corners, מלאו בגוון בהיר מהמשפחה. אם הצורה מכסה הכל — Format → Arrange → Send to back.

  1. הצורהInsert ← Shapes ← Rectangle ברוחב ארבעת הקארדים
  2. עיצובRounded corners, מילוי בגוון בהיר, בלי מסגרת
  3. שכבותFormat ← Arrange ← Send to back

למה מגש: הצורה מקבצת את ארבעת הקארדים לאובייקט ויזואלי אחד. העין קוראת "אזור KPI" במקום ארבעה ריבועים מרחפים.

בדיקה: לחיצה על קארד בוחרת את הקארד ולא את הצורה — סימן שהצורה מאחור.

2.5 · גרף 2 — מגמת מכירות חודשית (קו)

◆באיזה חודש נרשם שיא המכירות?

זו נקודת "הקשר השגוי" מהאזהרה בפתיחה: ב-Sales יש שלושה מפתחות תאריך — Order, Due ו-Ship. אם הקשר הפעיל אינו OrderDateKey, כל נקודה על הקו תזוז ותספר סיפור לא נכון. אם הגרף נראה מוזר — בדקו במסך Model מי הקו הרציף.

4.3 · בדיקה עצמית — האם הדשבורד מספר סיפור?

◆סכמו במשפט אחד: מה הסיפור העסקי המרכזי שהדשבורד שלכם מספר?

הסיפור המרכזי: עסק מרוכז מאוד. ארה"ב לבדה 57.4% מהמכירות (רמזור ירוק בודד), Bikes 86.2% מהקטלוג (פרוסת דונאט אחת), ושלוש מדינות מחזיקות 82% (Top 3 / Running %). הדשבורד צריך לצעוק "ריכוזיות" במבט אחד.

מבחן העקביות: [Total Sales] בקארד = סכום כל העמודות בגרף = 100% בשורה האחרונה של Running % = סכום הדונאט. אם אחד מהם לא מסתדר — יש פילטר נסתר על אחד הוויזואלים.

הלכידות היא מה שמבדיל דשבורד מאוסף גרפים: קארד, צבע, פרוסה ומצטבר — כולם מספרים את אותו סיפור מזוויות שונות.
